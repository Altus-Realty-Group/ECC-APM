## Release acceptance

1. Match current and historical operational records to exact DoorLoop identities. Keep unconfirmed activity distinct from inactive. Reconcile to the official Altus QuickBooks accounting directory and both ownership exports. These sources cover different populations and are not additive.
2. Identify what each source operation actually covered. Account for every record and field required by the UI, including withheld, unmatched, unresolved and provider-unavailable records. Carry property, owner, unit, tenant, lease, ledger and document relations through Working without conflating entities.
3. Publish the verified UI version and record an authenticated browser receipt with the exact route, source and deployment revision. Include reconciled counts, linked-card journeys, verified denied sessions, refresh and replay. Keep private record values out of public GitHub evidence.
4. Report the live UI link and evidence in #262. The pilot is an intermediate milestone. Full acceptance requires the agreed portfolio and workflow coverage and review of each outstanding discrepancy.
