## Protected property route activation

The source composition is in [workingPropertyCard.ts](../../server/routes/workingPropertyCard.ts). The loopback test exercises that factory, including current-session and exact property-grant HTTP calls, receipt checks and the card response with synthetic data.

- Confirm the target Control Plane deployment and ECC client registration through [#179](https://github.com/Altus-Realty-Group/altus-control-plane/issues/179). Supply the verified server-session lookup and keep the registered client assertion in the server's secret store.
- Bind both identity and company receipt lookups to their authoritative stores. The final Working read must enforce the exact company, actor, connection, property and authorization deadline. Verify the connection role, row-level permissions and existing [legacy exposure #107](https://github.com/Altus-Realty-Group/doorloop-sync-backend/issues/107) before reading customer data.
- Replace the legacy property-card handler when mounting this router under `/api/rpc`. Verify alternate request forms cannot fall through to the legacy reader. Prove a real authorized card and related records, plus a denied and revoked read against the same deployed revision.

## Release acceptance

1. Match current and historical operational records to exact DoorLoop identities. Keep unconfirmed activity distinct from inactive. Reconcile to the official Altus QuickBooks accounting directory and both ownership exports. These sources cover different populations and are not additive.
2. Identify what each source operation actually covered. Account for every record and field required by the UI, including withheld, unmatched, unresolved and provider-unavailable records. Carry property, owner, unit, tenant, lease, ledger and document relations through Working without conflating entities.
3. Publish the verified UI version and record an authenticated browser receipt with the exact route, source and deployment revision. Include reconciled counts, linked-card journeys, verified denied sessions, refresh and replay. Keep private record values out of public GitHub evidence.
4. Report the live UI link and evidence in #262. The pilot is an intermediate milestone. Full acceptance requires the agreed portfolio and workflow coverage and review of each outstanding discrepancy.
